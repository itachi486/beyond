## Registration and compatibility

Email + unique case-insensitive username + password. Registration immediately creates an active member and secure session, without mail delivery, password confirmation or email-verification gate. Required username is 3–40 ASCII letters/numbers/underscores; existing scrypt password requirements remain >=12 characters and <=256 bytes. Old account IDs, password hashes, credential versions, sessions and world ownership are preserved. Existing accounts receive deterministic unique migration usernames without inventing email verification. `verified_at` is not fabricated or used as an access requirement. Legacy verification/resend endpoints return410; old verification links explain that verification is no longer required and offer login.

Reset still uses an actual email transport and expiring hashed one-time token; it does not bypass email ownership. No RESEND_API_KEY/AUTH_EMAIL_FROM are configured, so real reset delivery is unavailable and returns an honest503. Registration has no provider dependency and sends no verification email. Secure cookies, normalized email, rate limits, Origin/JSON/CSRF checks and server ownership remain. No member gains admin permissions.

## HTML-as-JSON diagnosis: evidence, not speculation

User confirmed screenshot host/path `/admin/users`. Initial real admin login, repeated dashboard/users visits and refresh observed these GET routes returning JSON200: `/api/admin/catalog`, `/api/admin/dashboard`, `/api/admin/fantasy-overview`, `/api/admin/users`. The screenshot's exact two historical responses have no HAR and cannot be retroactively identified with certainty.

Later actual multi-browser execution reproduced HTTP503 with `Content-Type: text/html; charset=UTF-8` on GET `/api/user/auth/session` and `/api/public/universe`. Corresponding live Worker tail events at2026-10-30T20:01:08 UTC recorded `outcome=exceededCpu`, CPU10ms, `Worker exceeded CPU time limit.` This confirms an actual platform HTML response mechanism: Workers Free CPU termination, outside application catch handlers. There is no evidence that these reproduced responses came from SPA fallback. Current unknown API-route tests return JSON404. Earlier403/401/400/409 and injected500 cases also return JSON with correct statuses.

Safe log excerpt:

```json
{"path":"/api/user/auth/session","status":503,"contentType":"text/html; charset=UTF-8","outcome":"exceededCpu","cpuTime":10,"exception":"Worker exceeded CPU time limit."}
```

The shared client previously called response.json() blindly. Parent catalog/dashboard and child fantasy-overview loads could display identical raw parsing errors. New `readAPIResponse` checks type/status, rejects HTML/invalid/empty JSON without exposing bodies, logs only sanitized route/status/type and preserves safe JSON errors. One overview load now owns the dashboard's error/retry state; existing editorial shortcuts are retained through that aggregate response. No endless automatic retry. Abort/debounce/version guards prevent stale member-filter results. API routing includes `/api` and `/api/*`; unknown routes are JSON404; application exceptions are safe JSON500. Binary image successes intentionally remain images.

CPU work reduced by cached empty SQL schema templates, route-specific D1 table snapshots, metadata endpoints without DB reads and lazy image codec initialization. Sessions and ownership stay authoritative; credential hashing was not weakened. Observed successful member-session executions after optimization included5–7ms, versus earlier28–31ms samples; these are not a controlled performance benchmark or SLA. Cold/full snapshots, scrypt and image processing can still exceed10ms.

Attempted explicit CPU configuration was rejected by Cloudflare with code100328: CPU limits unsupported on Free. No upgrade/payment was made. User selected Free; the attempted override was removed and final settings have no CPU override. **This is not a claim that all platform503s are permanently eliminated.** Application JSON safeguards cannot intercept a runtime kill before a response. Official limits and this distinction: https://developers.cloudflare.com/workers/platform/limits/ (Free HTTP and Cron CPU10ms, occasional burst allowance, exceededCpu outcome).
